# Watch Party
Registration, login, and logout use PHP sessions and MySQL. Registering signs the
user in immediately. The home page renders Log in and Register only for guests.

## Run locally
The local `watch_party` database and limited `watch_party_app` MySQL account are
configured in the ignored `.env` file. From the project directory run:

```powershell
.\dev.ps1
```

Open http://127.0.0.1:8000. The script finds PHP on PATH and enables `pdo_mysql`
for this process when necessary.
Static HTML preview servers cannot execute the authentication backend.

On another machine, use PHP 8.2+ with PDO MySQL, import `database/schema.sql`
using a database administrator, create an application account with only SELECT,
INSERT, UPDATE, DELETE access to `watch_party.*`, then copy `.env.example` to `.env`
and set the `WATCHPARTY_HOST`,
`WATCHPARTY_PORT`, `WATCHPARTY_DATABASE`, `WATCHPARTY_DATABASE_USERNAME`, and
`WATCHPARTY_DATABASE_PASSWORD` values accordingly. `Dotenv::createImmutable()`
loads these into `$_ENV` and `$_SERVER`, not the `getenv()` process environment.

## Security and hosting

- Passwords use bcrypt at cost 12 with a cryptographically random per-password
  salt generated by `password_hash`; only the resulting hash is stored.
- Registration requires 12–72 bytes, with matching password confirmation.
- Database queries use native prepared statements. Emails are normalized and
  unique. All user content rendered into HTML is escaped.
- Sessions use HttpOnly, SameSite=Lax cookies, Secure cookies on HTTPS, a new
  session ID and CSRF token on sign-in, and a two-hour inactivity timeout.
- All authentication POSTs require CSRF tokens; logout accepts POST only.
- MySQL enforces a shared limit of 20 authentication attempts per IP per 15
  minutes, including across new browser sessions. Login failures are generic.
- Credentials and runtime session files are ignored by Git.

For production, require HTTPS and configure PHP with `display_errors=Off`.
Apache requires `mod_rewrite` and `AllowOverride All` for the included `.htaccess`.
Other servers must serve only the entry points (`index.php`, `login.php`,
`register.php`, `logout.php`) and `assets/`; never expose configuration, app,
database, vendor, tests, dotfiles, or runtime files. The bundled development
router uses this allowlist. If TLS terminates at a proxy, configure the server's
HTTPS flag from the trusted proxy and preserve the actual client IP securely.
